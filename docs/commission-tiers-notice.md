# 手数料 逓減制の導入 — 講師向け告知文・規約追記の草案

作成日: 2026-08-06 / 更新: 2026-08-17 / ステータス: **運営判断は確定・法務／税務レビュー待ち（未公開）**

導入する制度は次のとおり。

| 同一生徒の受講回数 | 運営手数料 | 講師の受取率 |
|---|---|---|
| 1〜10回目 | 18% | 82% |
| 11〜50回目 | 15% | 85% |
| 51回目以降 | 10% | 90% |

- 回数は「**同じ生徒 × 同じ講師**」の組み合わせごとに数える
- 数えるのは**成立したレッスンのみ**（キャンセル・返金分は含めない）
- 料率は**予約成立時点**で確定し、後から変わらない
- カウントの起点は **その講師と生徒の初レッスン**。制度の「開始日」という区切りは設けない
  （2026-08-17時点でまだ講師へ展開していないため、既存実績との整合を取る必要がない）

> ⚠️ **本文書は法律専門家・税理士のレビューを受けていません。** 特に規約案と税務の整理（E章・源泉徴収）は、公開前に確認を受けることを推奨します。

## A. 講師向け告知文（メール／お知らせ用）

件名: **【Geidai Connect】運営手数料の引き下げについて（継続レッスンの割引制度）**

---

講師の皆さま

いつも Geidai Connect をご利用いただきありがとうございます。

このたび、同じ生徒さんへのレッスンを継続していただいた場合に、**運営手数料を段階的に引き下げる制度**を導入いたします。手数料が下がった分は、そのまま**講師の皆さまのお受け取り額の増加**となります。生徒さんのお支払い額は変わりません。

### 新しい手数料

| 同じ生徒さんへの受講回数 | 運営手数料 | お受け取り |
|---|---|---|
| 1〜10回目 | 18% | 82% |
| 11〜50回目 | **15%** | **85%** |
| 51回目以降 | **10%** | **90%** |

例）レッスン料 10,000円の場合
- 1〜10回目：お受け取り 8,200円
- 11回目以降：お受け取り 8,500円（**+300円**）
- 51回目以降：お受け取り 9,000円（**+800円**）

### カウントの起点

回数は、**その生徒さんへの初回レッスンから**数えます。過去にレッスンをされている場合、その実績もそのまま回数に含まれます。すでに同じ生徒さんへ10回以上レッスンをされている場合は、次のご予約から15%が適用されます。

「この日から開始」という区切りは設けていません。本制度の運用開始時点で、すべての講師の皆さまの累計回数がそのまま反映されます。

### ご確認方法

「予約一覧（講師用）」ページに、生徒さんごとの受講回数と、次の割引までの残り回数を表示しています。各予約には手数料差引後のお受け取り額も表示されます。

### 補足

- 回数は「同じ生徒さん」ごとに数えます。生徒さんが変われば1回目からの計算となります
- 回数は**生徒アカウント単位**で数えます。ご家族・きょうだいでも、アカウントが異なれば別々の計算です（アカウントは受講される方お一人につき1つご登録いただきます）
- キャンセル・返金となったレッスンは回数に含みません
- 手数料率は**ご予約が成立した時点**で確定します。予約後に回数が増えても、その予約の料率は変わりません
- スタジオ代・出張費は手数料の対象外です（従来どおり）
- 手数料は税込レッスン料に対して計算します。なお、講師ご自身の課税売上高の判定に用いるのは**レッスン料の全額**であり、手数料差引後のお受け取り額ではありません

ご不明な点はお問い合わせフォームよりご連絡ください。

Geidai Connect 運営

## B. 利用規約への追記案

**第6条（料金・支払い）の直後に「第6条の2」として新設**する想定。
既存条文の番号を変えずに済むため、改定の影響範囲が小さい。

### 第6条の2（講師への支払い・運営手数料）

1. 運営者は、生徒が支払ったレッスン料から次項に定める運営手数料を控除した額を、
   講師に対して支払うものとします。スタジオ代・出張費その他の実費は、
   運営手数料の算定基礎に含めません。

2. 運営手数料の料率は、当該予約の時点における「同一の生徒と当該講師との間で
   成立したレッスンの累計回数」に応じ、次のとおりとします。

   | 累計回数 | 料率 |
   |---|---|
   | 10回に満たない場合 | レッスン料の18% |
   | 10回以上50回に満たない場合 | レッスン料の15% |
   | 50回以上の場合 | レッスン料の10% |

3. 前項の累計回数は、生徒の決済が完了したレッスンのみを対象として算定し、
   キャンセル又は返金となったレッスンは算入しません。
   累計回数は生徒の登録アカウント単位で算定するものとし、
   利用者が異なれば、同一の世帯に属する場合であっても合算しません。

4. 各予約に適用される料率は、当該予約が成立した時点で確定し、
   その後に累計回数が増加した場合であっても、当該予約について遡って変更されません。

5. 運営者は、料率及び前各項の条件を変更することがあります。
   変更は、第14条（規約の改定）に従い、本サービス上での告知をもって効力を生じるものとし、
   変更前に成立した予約については従前の料率を適用します。

6. 運営者は、各月の末日を締切日とし、当該月に実施されたレッスンに係る前項の支払額を、
   翌月15日（同日が土日祝日の場合は翌営業日）までに、講師が指定する金融機関口座へ
   振り込む方法により支払います。振込手数料は運営者の負担とします。
   ただし、支払額の合計が3,000円に満たない場合は、当該金額を翌月以降に繰り越し、
   合計額が3,000円に達した月の支払日に支払うものとします。

7. 締切日後にキャンセル・返金が生じた場合、運営者は、当該返金に係る額を
   翌月以降の支払額から控除することができます。

### 附則

本条は、改定後の本規約の効力発生日から施行します。
第2項の累計回数は、施行日前に成立したレッスンを含め、当該生徒と当該講師との間の
最初のレッスンから算定します。ただし、施行日前に成立した予約に適用された料率は、
遡って変更しません。

> 運営メモ: 講師への展開前なので「制度開始日」を置かず、初レッスンからの通算で数える。
> 施行日は規約改定そのものの効力発生日（第14条の告知手続きに従う）と一致させ、
> 手数料の計算式には日付の分岐を入れない。

### あわせて必要な改定（アカウントの単位）

累計回数をアカウント単位で数える前提を成り立たせるため、次の2点を同時に改定します。

**第5条（登録）に第2項として追加**

> 2. アカウントは、本サービスを利用する方お一人につき1つとします。
>    複数の方が1つのアカウントを共用して本サービスを利用することはできません。
>    18歳未満の方の登録は、第5条の2に従い、受講される方ご本人のアカウントとして行うものとします。

**第9条（禁止事項）に1項目を追加**

> - アカウントを第三者と共用し、又は第三者に利用させる行為

※ 実装は `users/{uid}` 単位のカウントで、この規約案と一致している（`priorLessonCount` は
生徒 uid × 講師 uid で集計）。規約側を実装に合わせる形なのでコード変更は不要。

## C. 想定問答（問い合わせ対応用）

**Q. 生徒の支払額は変わりますか？**
変わりません。手数料が下がった分は講師の受取額の増加となります。

**Q. 回数はいつから数えますか？**
その生徒さんへの**初回レッスンから**です。「この日から開始」という区切りはありません。

**Q. 過去のレッスンは回数に入りますか？**
入ります。ただし過去の予約の手数料が遡って下がることはありません。

**Q. 生徒が別のコースを受けた場合も同じカウントですか？**
同じです。コース・レッスン形態（対面／オンライン等）を問わず、同じ生徒さんとの累計回数で数えます。

**Q. 予約したあとに10回目を超えました。この予約は15%になりますか？**
なりません。料率は予約が成立した時点で確定します。次のご予約から15%が適用されます。

**Q. 生徒が予約をキャンセルしました。回数はどうなりますか？**
返金されたレッスンは回数に含みません。

**Q. 家族が同じ講師に習っている場合、合算されますか？**
合算されません。アカウント（生徒）ごとに数えます。

**Q. きょうだいで1つのアカウントを使っています。回数はどうなりますか？**
アカウントは受講される方お一人につき1つご登録いただく決まりです（規約第5条第2項）。
共用されている場合は、お手数ですが受講される方ごとにアカウントをご登録ください。
移行前の受講実績は、ご連絡いただければ運営側で該当アカウントへの引き継ぎ（回数の付け替え）を検討します。

> 運営メモ: 実装は uid 単位のカウントなので、アカウントを分けた時点で新アカウントは0回から始まる。
> 引き継ぎを認める場合は Firestore 側での手当てが必要（自動化はしていない）。件数が出てから対応する。

## D. 支払サイクル（推奨案）

**月末締め・翌月15日払い / 振込手数料は運営者負担 / 最低支払額3,000円（未満は翌月繰越）**

根拠:

| 論点 | 判断 |
|---|---|
| 締め〜支払の期間 | レッスン実施日から最長でも45日。60日以内に収まる設計にしておくと、下請法・フリーランス新法の論点が生じても問題にならない |
| 資金の余裕 | Stripe から運営口座への入金は数営業日。翌月15日なら十分に間に合う |
| 返金リスク | 締切後の返金は翌月以降の支払額から控除（規約第6条の2第7項）。先に払いすぎて回収不能になる事態を防ぐ |
| 振込手数料 | 運営者負担が説明しやすい。18%の手数料に含まれるという建付けにできる |
| 少額振込 | 1件だけの月に数百円を振り込むとコスト倒れ。3,000円の下限で回避 |

**法令の当てはめ（下請法・フリーランス新法）**

本サービスは第4条のとおりマッチングプラットフォームであり、レッスンの契約当事者は講師と生徒です。
運営者が講師に業務を委託しているわけではないため、下請法・フリーランス新法（特定受託事業者に係る
取引の適正化等に関する法律／2024年11月施行）の直接の適用対象ではないと整理できます。
ただし解釈に幅がある領域なので、**支払期日を60日以内に置いておけばこの論点自体が生じません。**
上記の推奨案はその前提で組んでいます。

**源泉徴収の扱い（運営方針：不要として運用する）**

所得税法第204条第1項は「技芸の教授・指導の報酬」を源泉徴収の対象としていますが、
本件はレッスン料の支払者が生徒（個人）であり、通常、個人は源泉徴収義務者に当たりません
（所得税法第204条第2項第2号）。運営者は収納代行の立場で講師の代わりに受領・精算しているに
すぎず、運営者自身が報酬の支払者となるわけではありません。

以上より、**源泉徴収は行わない**方針で運用します。告知文・規約案もこの前提で確定しています。
講師への支払明細には源泉徴収税額の欄を設けません。

> ⚠️ この整理は税理士のレビューを受けていません（G章の宿題）。
> 仮に「運営者が支払者にあたる」と整理し直す必要が生じた場合、10.21%の源泉徴収、
> 支払調書の作成、支払額計算の変更が発生します。実装上は `reservationPayouts` に
> 源泉税額のフィールドを足すことになるため、**確定前に大量の支払実績を作らないほうが安全**です。

## E. 消費税・インボイスの整理

### 前提：本サービスは「収納代行」モデル

利用規約第4条により、レッスンの契約は**講師と生徒の間**で成立し、運営者は場の提供者です。
したがって会計上は次のようになります。

| 項目 | 帰属 |
|---|---|
| レッスン料 10,000円 | **講師の売上** |
| うち手数料 1,800円 | **運営者の売上** |
| 講師への支払 8,200円 | 運営者の売上ではない（預り金の精算） |

**運営者の課税売上はレッスン料全額ではなく、手数料だけです。** これは非常に有利な構造です。

### なぜ有利か（インボイス制度との関係）

仮に「運営者がレッスン料全額を売上に計上し、講師への支払を仕入として計上する」モデルだった場合、
**免税事業者の講師から仕入税額控除ができず、その消費税を運営者が被る**ことになります。
講師の多くは売上1,000万円以下の免税事業者と考えられるため、影響は小さくありません。

収納代行モデルではこの問題が起きません。**講師が免税事業者かどうかは運営者の納税額に影響しません。**

### 運営者がやるべきこと

1. **適格請求書発行事業者の登録**（未登録なら）
   運営者は講師に対して「手数料」を請求する立場です。
   講師が課税事業者の場合、その講師が手数料分の仕入税額控除を受けるには、
   運営者が交付する適格請求書（登録番号入り）が必要です。
   未登録だと、課税事業者の講師にとって不利になります。

2. **手数料の明細を講師へ交付**
   月次の支払明細に「レッスン料合計 / 手数料 / 消費税額 / 支払額」と登録番号を記載します。
   これが適格請求書の要件を満たす形にします。

3. **生徒への領収書は講師名義が原則**
   収納代行モデルでは、レッスンの売主は講師です。
   運営者名義で発行する場合は「講師の代理として受領」である旨を明示します。

### 内税・外税

現行の利用規約第6条で「表示金額は消費税を含む」としているため、**手数料も税込ベースで統一**するのが
最も単純です。

```
レッスン料 10,000円（税込）
  × 18% = 手数料 1,800円（税込。うち消費税相当額 約163円）
  → 講師への支払 8,200円
```

**講師が誤解しやすい点**（告知文に明記を推奨）:
講師自身の課税売上高の判定に用いるのは**レッスン料全額（10,000円）**であって、
手取り（8,200円）ではありません。年間1,000万円の判定はレッスン料ベースです。

### 運営者側の納税

手数料収入の規模によっては、簡易課税制度（第5種・サービス業／みなし仕入率50%）や
2割特例が有利になる場合があります。**これは事業規模次第なので税理士にご相談ください。**

> ⚠️ 本節は制度の一般的な整理であり、個別の税務判断ではありません。
> 特に **収納代行としての整理が税務上も認められるか**（＝手数料のみを課税売上とできるか）は、
> 契約書・規約・資金の流れの実態で判断されます。**税理士の確認を強く推奨します。**

## F. 手数料情報の秘匿（実装済み）

生徒に手数料率・講師の取り分が見えないよう、データを分離しています。

- 予約本体（`reservations`）は**生徒本人も読める**ため、ここに料率を置くと
  画面に出していなくてもブラウザの開発者ツールから読めてしまう
- そこで手数料の明細は別コレクション **`reservationPayouts`** に保存し、
  Firestore ルールで **担当講師本人と admin のみ read 可**とした
- ドキュメント ID は予約 ID と同一にして突き合わせる
